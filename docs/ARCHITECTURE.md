## Actual entry and dependencies

`index.html:150–167` directly loads PDF.js/PDF-lib and classic scripts in order: domain → globals → native runtime → session → pen/palettes → wizard → strokes/history/eraser → export → renderer/input → remote → DOM wiring → Board2 UI integration. `events-init.js` starts restore; `board-2.0.1-ui.js` waits for `window.boardRestorePromise`, then successful recovery ACK before enabling persistence/first-run wizard.

`app.js` contains another sequential loader and is copied to dist, but the current index does not load it. `js/init.js`, `runtime.js`, `overlay.js` and `diagnostics.js` are an optional parallel module/diagnostic path, also not loaded by this index. Do not describe those as active owners or delete them without checking their documented/manual use.

## Historical reproduced defects and repair evidence

The initial independent audit ran the then-current `persistSessionState` body in a memory-only VM, with only IndexedDB completion/localStorage failure supplied as fixtures. No source or fixture file was written.

1. Start saving PDF A; while its bytes write awaits, switch live bytes/document to B and mark dirty. Complete A write, then save B. Observed result: `secondSaveSucceeded=true`, JSON snapshot B, PDF byte65(A), expected66(B), dirty=false. A's completion clears B's dirty flag (`session-pdf-toolbar.js:548–570`; PDF replacement marks dirty at `render-doc-draw.js:355`).
2. With a valid saved A pair, save PDF B successfully to IndexedDB, then throw quota error on localStorage commit. Observed result=false, JSON snapshot A, PDF byte66(B), expected old65(A), dirty=false. Returning false alone does not preserve the last good pair.

These correctness/data-integrity findings were fixed in the existing owner. A subsequent real two-context IndexedDB fixture reproduced cleanup deleting another writer's backup; the final whole-entry Web Lock fixes that supported competing-WebView path. Final real-browser guarded-entry checks cover matching restore reads, clean-writer byte capture, actual quota rollback and missing-lock fail-closed behavior. See `docs/reviews/board-2.0.1-session-persistence.md`.

## Approved minimum boundary closure

1. **Session writer repair in the existing session file — implemented and independently reviewed.** Serialize all explicit/autosave/visibility saves through one writer; capture stable snapshot/PDF identity; never clear another document's dirty flag. Capture the last successful raw JSON/PDF pair before changes, verify the actual serialized commit, and restore/preserve that pair on stale completion or failed commit. A failed rollback must hold persistence, retain the original pair/backup and surface failure; it must never authorize update with a true result. Existing legacy key/schema1 must remain readable. The parent selected graceful race/failure repair first; this is not a claim of crash-atomic two-store persistence.
2. **One active-page commit path — implemented and independently reviewed.** Reuse `saveCurrentStrokeState`/`BoardState.savePageState` and make compatibility PDF/blank snapshots derived at that boundary. Remove redundant caller commit work only after existing page/history/session/work-file tests demonstrate equivalence. Keep legacy read migration; do not delete old saved fields or introduce a global store/refactor all scripts.
3. **Explicit resource/replacement boundaries — traced in existing owners.** Document and, where a failing test demonstrates a gap, fix PDF load/unload/cancel, cache pin, gesture/trial cancel and overlay timer lifecycle in their existing owners. Page restore and PDF replacement are controlled state-replacement exceptions.
4. **Documentation closure — this actual map and paired review records.** Each requirement maps to one actual owner, permitted mutators/callers, cleanup path and relevant behavioral evidence. Distinguish planned exceptions from implemented boundaries. A file split, new controller folder or test count alone does not prove responsibility separation.

Required writer assertions: deferred A→B and A→blank changes never produce mixed pair; overlapping callers cannot publish out of order; rejected/quota/IDB write leaves last good pair readable; stale or failed save never returns true/clears dirty; persistence hold prevents writes; update authorization is not reached on false/rejected persistence; successful save is verified before launch. Beforeunload cannot await a Promise reliably, so it remains best-effort rather than proof of graceful checkpoint completion.

## Compatibility limits and install boundaries

The current old reader always reads `last-pdf`; a new versioned byte key in JSON would require an old-reader compatibility strategy before adoption. Current signed metadata validators require schema1. Helper rollback verifies schema compatibility and backs up the closed current profile; it does **not** automatically restore the earlier checkpoint before launching the previous version (`bin/boardcanvas-recovery.rs:141–166`). Thus immutable-key/snapshot-pointer or schema2 is a separate design decision, not silently folded into this minimum repair. Full process-crash atomicity is not established by the graceful-save repair.

The earlier beta.4-labeled UI's `Signed update releases are not configured on this build` meant native `public_key().is_ok() && production_feed_configured()` is false; the message alone does not prove which build feature/key failed. A package-context path and normal path were observed, but those names alone did not prove distinct binaries: the later physical hashes matched the old test executable. Do not infer production identity from a UI version or path label. Direct NSIS replacement would invalidate an existing journal's current executable fingerprint; it is not a verified signed update. Prefer verified work-file export/closed backups and the genuine production app's signed updater path. Never fabricate beta.4 as the previous production baseline or reset a journal to bypass the mismatch.

## Ponytail disposition

- `reuse:` keep existing pure BoardState, replacement manager, save/restore functions, renderer and native command modules; make writes/lifecycle explicit before adding files.
- `yagni:` the old proposal's blanket controller/IPC/platform conversion is not a prerequisite for this scope. No new dependency, framework, event bus or schema2 rollout is required merely by the audit.
- `delete:` uncalled raw session-byte save/clear helpers were removed after reference checks as part of the cache repair. No further deletion is mandated here; inactive loader/diagnostic paths remain separate reference-checked cleanup candidates.

Net: no justified dependency removal or line-count target is asserted. The useful reduction is duplicate ownership/commit work, verified through behavior rather than files moved.

## Final boundary evidence and resource lifecycle

- Session closure: source SHA256331952183BF62C37D60C98E1D418C0FB7E940CEDD2265920C537AB586521690E; independent exact-helper real IDB12 assertions and guarded-entry two-page real Web Locks/IDB/localStorage6 checks.
