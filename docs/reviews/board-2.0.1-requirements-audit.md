## 결론

**전체 요구를 출시·실환경 검증까지 완료했다고 말할 수 없다.** 대부분의 앱 내부 기능은 실제 구현 경로와 자동·브라우저 검증 기록이 있다. 업데이트는 배포 설정 및 서명된 설치 경로가 비활성이고, Drive는 실제 OAuth·캐시 구현은 있지만 배포 클라이언트 설정과 실계정 연결 확인이 남는다. 감사에서 발견한 칠판 PDF 내보내기의 바깥 필기 누락은 워커가 수정했고 독립 소스/회귀검증으로 확인했다.

`구현 확인`은 소스 기능 존재와 확인한 검증 범위를 뜻한다. 실물 터치센서·리모컨, 최신 Windows 네이티브 앱, 실제 OAuth·업데이트·OS 저장창 검증 완료를 뜻하지 않는다.

## Actionable finding

**P1 — PDF 없는 칠판의 바깥 필기가 기본 내보내기에서 잘림 → 수정 확인.**

- 요구: canonical README 283–285. 칠판은 기본 칠판 영역을 사용하되 밖 필기가 있으면 잘리지 않게 출력 영역을 확장한다. `PDF 바깥 필기 포함`은 PDF 페이지의 선택사항이며 PDF 없는 칠판에도 강제하는 요구가 아니다.
- 수정 전 구현: `js/board-export.js:136`은 blank branch에도 `Boolean(options.includeOutsideInk)`를 적용했다. 기본 unchecked 값에서는 `pageBounds`가 `js/board-export.js:12`에서 즉시 기본 frame만 반환했다. `js/render-doc-draw.js:212`는 값을 변경하지 않고 전달했다.
- 독립 재현: 실제 exporter와 pdf-lib, 800×1100 blank frame, stroke width10/point(-100,-100), PDF원본 없음. 미체크 출력 612.2836×841.89; 체크 출력692.6459×922.2522. 미체크 canvas는 기본 frame을 벗어난 필기를 담지 못한다. pixel 테스트가 아닌 출력 영역 차이 재현이며 데이터가 출력 범위 밖이라는 소스 근거와 함께 확인했다.
- 수정 및 독립 확인: 코디네이터 전달 후 워커가 `js/board-export.js:136`을 `pageBounds(frame, entry.strokes, true)`로 바꾸었다. `tests/board-export.test.js`에 blank-only 및 혼합문서의 포함한 blank가 확장되고 PDF는 기본 crop을 유지하는 회귀검증을 추가했다. 감사자는 소스를 수정하지 않았다.

## False positive / 변경·보류 이유

- 초기 3초 줌과 세로 슬라이더가 없다는 주장은 이후 사용자2초 지시 및 슬라이더 제거/돋보기 피드백 결정으로 대체되어 finding으로 채택하지 않는다. 팔레트3초는 유지된다. README의 초기 문구와 최신 변경 기록은 구분해야 한다.
- Drive 로그인은 템플릿/가짜 로그인으로 분류하지 않는다. 실제 Rust OAuth/Drive HTTP/cache 구현이 있고, 필요한 공개 OAuth client 설정이 없으면 명확한 설정 오류를 반환한다. 구현과 실제 배포 설정/실계정 성공은 별개다.
- updater public key placeholder 판별 함수의 존재는 배포 설정 완료를 뜻하지 않는다. 현 config는 updater를 활성화하지 않고 feature/bundle/signature endpoint가 준비되지 않았으므로 배포 미완료로 분류한다.
- 감사 중 워커가 변경한 개발자 탭 전역 초기화의 TDZ 가능성을 코디네이터에 전달했고 즉시 수정이 진행되었다. 이 후속 변경은 별도 독립 코드/AGY 리뷰로 처리하며, 기준 커밋 전체의 지속 결함으로 표시하지 않는다.

## 후속 과제 / 선택 대기 / 출시 필수 미완료의 구분

- **이번 버전 필수 아님:** ESP32 전용 펜, Bluetooth/2.4GHz 전용 하드웨어 및 레이저 포인터(canonical README198–206). 미구현을 이번 버전 blocker로 세지 않는다.
- **사용자 선택 대기 제안:** 전체화면 측정 overlay. 승인된 개발자창 시험/측정의 미구현으로 세지 않는다.
- **실기 결정/검증:** threshold 실물 조정, 센서 입력/리모컨 입력, 지우개 사용 후 pen복귀 최종 수용, 최신 네이티브 창 버튼 및 OS 저장창. browser/합성 테스트로 대신 완료 처리하지 않는다.
- **실제 출시 완성에 필요한 외부 작업:** OAuth Desktop client/consent/Drive API 준비 후 빌드와 실계정 시험, updater endpoint·서명 키·feature/config·bundle 준비 후 실제 배포/다운로드/실패 복구/재시작 선택 시험.

## 이번 감사의 검증 상태

- 첫 독립 전체 JS 테스트는 워커 후속 탭 변경 중 **49/50**, `tests/board-state.test.js:715`의 모드 기대값이 실패했다. 코디네이터에게 전달했고 워커가 기대조건/회귀검증을 갱신했다. 안정된 현재 미커밋 파일을 다시 독립 실행해 **51/51 통과**했다. 이전 커밋265ba44의 기록은50/50이며 현재 결과를 과거 커밋 결과로 덮어쓰지 않는다.
- 독립 blank export 재현은 위 finding을 확인했다. 소스 외부 파일을 생성하거나 실제 작업·브라우저·사용자 설정을 변경하지 않았다.
- 기존 구현/설정/터치의 Codex 및 Antigravity 완료는 각각 기존 리뷰 파일의 독립 실행 주체/세션/최종 범위 기록을 확인한 것이다. 이번 전체 요구 감사에서 새 AGY 전체 소스 리뷰를 수행했다고 주장하지 않는다. 진행 중 후속 코드 변경의 두 리뷰는 별도 코디네이터 책임이다.
- 본 감사는 현재 안정된 소스의 요구 대응 확인을 완료했지만 **전체 출시 검증 완료를 승인하지 않는다**. 업데이트 배포·Drive 실계정·실물 입력·최신 네이티브 동작 등 위 남은 항목을 유지하고, 후속 코드 리뷰 결과는 코디네이터가 최종 현재 상태에 반영해야 한다.
