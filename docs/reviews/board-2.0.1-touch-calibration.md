## False positives, design decisions and deferred validation

- AGY delta claimed a third touch ends production gestures because `endMultiTouchGesture` itself lacks an ID guard. Actual pointerup/pointercancel listeners guard with `gesture.pointers.has(event.pointerId)` before calling it. Independent execution of those exact listeners accepted a non-primary second touch and proved an unknown third up preserves the original pair. False positive; no redundant guard added.
- AGY primary asserted browsers always emit pointercancel after lostpointercapture, implying suppression cleanup was guaranteed. This assertion was not relied on. Explicit window release cleanup resolves the independently identified outside-canvas case.
- The fixed initial midpoint anchor is an explicit accepted requirement. Production phase transitions rebase their camera/span/centroid before continuing, avoiding a handoff jump; updating the zoom anchor to the current fingers would change the agreed behavior. AGY's alternate-anchor concern is deferred as a design alternative, not an unresolved defect.
- Applying a raw maximum span as the chosen onset distance is intentionally transparent and explicit. A large full gesture will produce a large threshold; the guidance and proposed-value preview make that choice reviewable, and the draft can be edited or cancelled. Deriving a first crossing from the existing threshold would make calibration circular and was not adopted.
- Initial 12/12/40px thresholds are provisional test defaults, not hardware certification. Real bezel-touch hardware, OS-specific touch delivery, palm/pen combinations and device-specific tuning remain manual acceptance items. Synthetic handler traces and mathematical probes are not real hardware testing.
- Fullscreen overlay calibration remains a user-choice proposal outside this implementation; no acceptance of that proposal is recorded here.
